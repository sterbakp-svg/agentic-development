# Checklist T-020: platform limits spike (Copilot Studio)

Who: product owner. Time: about 3 to 4 hours, in one or two sessions. The result form at the end decides option A, B or C from `docs/05-mvp-copilot-studio.md`.

UI names in this checklist can differ from the real screen. A step marked `(check the UI name)` is written by goal; use the nearest menu and write the real name in the result form.

## Prerequisites

- A Power Platform **test environment** (a Developer environment is enough), region **Europe**. Never use the production tenant or a production environment.
- A Copilot Studio trial or license in that environment. Check in the Power Platform admin center that the environment has Copilot Studio capacity (check the UI name). Do not buy anything; if a payment is asked, stop and tell the lead.
- No mailbox, no real personal data. The only test inputs are the golden profiles in `pilot/copilot-studio/spike/generated/`. They are fictional.
- On your Mac: Node.js 20 or newer (`node --version`), Python 3.10 or newer (`python3 --version`), Visual Studio Code for Apple silicon (arm64), and a checkout of this repository on the branch the lead gives you.
- An empty agent named `Spike Agent` in the test environment, language English (create it in the Copilot Studio web app: Create > New agent > skip the setup chat, name it, Create; check the UI name).

## Part 0. Build the paste files (5 minutes)

1. In the repository folder run: `node pilot/copilot-studio/spike/build.mjs`
   - Check: it prints a table of file names with character counts, and the last line `self-check: render equals expected-instructions.md for both golden examples`. If it throws, stop and send the message to the lead.
2. The files are in `pilot/copilot-studio/spike/generated/`. They are built from `prompts/`, `templates/`, `examples/` and `evals/`; never edit them by hand, run the script again instead.
   - `prompt-option-a.txt`: generator prompt, then the template, the slot definitions (`template.json` as it is), and two full examples (profile, slots, rendered instructions). Ends with the heading `# PROFILE`.
   - `prompt-option-b.txt`: the same, but the two examples carry profile and slots only, without the rendered instructions. This is the shortened form of option B.
   - `input-cio-insurance.json`, `input-tprm-analyst.json`: the golden profiles. Paste one of them as the prompt input.
   - `flow-template-body.txt`, `flow-values-cio-insurance.json`, `flow-values-tprm-analyst.json`, `flow-values-injection.json`, `flow-slot-names-all.txt`, `flow-slot-names-llm.txt`, `flow-slot-limits.json`, `flow-expressions.txt`: inputs for the flow in part 3.
3. Write the character counts printed by the script into the result form, point 1.
4. Create the folder for your results: `mkdir -p pilot/copilot-studio/spike/results/cio-insurance pilot/copilot-studio/spike/results/tprm-analyst`. Git ignores this folder.

## Part 1. Prompt tool accepts the long prompt (point 1)

5. Open `Spike Agent`. Go to **Tools > Add a tool > New tool > Prompt** (check the UI name). Name it `GenerateEmailTriageSlots`.
6. Add one text input named `profile_json` (check the UI name). Sample value for the editor test: the content of `input-cio-insurance.json`.
7. Open `prompt-option-a.txt` in a text editor, select all, copy, and paste it into the instruction box of the prompt tool. At the end of the text, below the line `# PROFILE`, insert the input `profile_json` with the editor's insert button (check the UI name). Save.
   - Check: the editor accepts the text without an error or a cut. Write down: accepted yes/no, any character counter value, the exact error text if there is one.
8. Look at the part of the text with `{{agent_name}}`, `{{user_name}}` and the other markers from the template. Check: they are shown as plain text and not as input variables or errors. Write down what you see (this tells us whether the double braces need escaping).
9. If step 7 failed, clear the box and repeat steps 7 and 8 with `prompt-option-b.txt`. Write down the result in the form. If both fail, stop part 1 and mark option C as needed.
10. Set the output of the prompt tool to **JSON** (check the UI name). If the editor asks for a sample or schema, paste the example output from `examples/cio-insurance/slots.json`. Write down which model is selected for the tool and the data location or region shown for it (check the UI name).
    - Check: the editor lets you save with JSON output. Write down what the editor offers (sample only, schema, or neither).

## Part 2. Valid JSON, 10 runs for each golden profile (point 2)

Use the option that was accepted in part 1 (A first). If you tested both, also run the 10 runs for B only when A was refused.

11. In the prompt tool test panel, set `profile_json` to the content of `input-cio-insurance.json` and click **Test** (check the UI name).
    - Check: a response appears. Write down the run time shown, if any.
12. Copy the whole response and save it as `pilot/copilot-studio/spike/results/cio-insurance/run-01.json`. Copy it exactly as shown, including any code fence or extra text.
13. Repeat steps 11 and 12 until you have `run-01.json` to `run-10.json`. Do each run as a fresh test (click Test again; do not edit the prompt in between).
14. Repeat steps 11 to 13 with `input-tprm-analyst.json`, saving into `results/tprm-analyst/`.
15. Run the helper for each folder:
    - `node pilot/copilot-studio/spike/validate-folder.mjs examples/cio-insurance/profile.json pilot/copilot-studio/spike/results/cio-insurance`
    - `node pilot/copilot-studio/spike/validate-folder.mjs examples/tprm-analyst/profile.json pilot/copilot-studio/spike/results/tprm-analyst`
    - Check: each prints one line per file with `file`, `parses`, `ok` and `errors` (only counts, no content), and a last line `parsed x/10, validator ok y/10`. A file with a code fence or extra text around the JSON counts as not parsed. Write x and y into the result form.
16. The helper wraps the reference check `python3 -I reference/composer_ref.py validate templates/email-triage/v1 <profile.json> <slots.json>`. You can run it by hand on one file to see the error messages. Do not paste those messages into chats or tickets if they came from real data; here they come from golden data, so you may copy them into the form.
    - Check: write into the result form the most frequent kind of failure (not parsed, wrong shape, too long, forbidden content, undeclared placeholder, other) from the helper counts and a look at the failing files.

## Part 3. Agent flow renders the template and reproduces the golden output (point 3)

The spike tests the string functions only. The flow gets all slot values already merged (computed values and generated slots) in one JSON text. Computing the computed slots in the flow is T-024.

17. In Copilot Studio open **Flows** (agent flows) and create a new agent flow named `Spike_RenderTest_email-triage_v1` (check the UI name). Trigger: **When an agent calls the flow** (check the UI name). Add one text input `values_json`.
18. Add the actions below in this order. The expressions are in `pilot/copilot-studio/spike/generated/flow-expressions.txt`; copy them from there, do not type them. Use the exact action names (spaces become underscores in expressions).
    1. **Initialize variable** `nl`, String, value from block `nl`.
    2. **Initialize variable** `body`, String, value: the full content of `flow-template-body.txt` (paste it as plain text; line breaks must stay).
    3. **Initialize variable** `tmp`, String, empty.
    4. **Compose** `values`: block `values` (use the dynamic content `values_json` if the expression does not fit).
    5. **Compose** `names`: block `names`. **Compose** `names_llm`: block `names_llm`. **Compose** `limits`: block `limits`.
    6. **Set variable** `body`: block `prepare`.
    7. **Condition** with block `condition tools`: if yes, **Set variable** `body` with block `drop tools`.
    8. **Condition** with block `condition org_rule`: if yes, **Set variable** `body` with block `drop org_rule`.
    9. **Apply to each** over the output of `names`. In its settings turn **Concurrency control** off (check the UI name). Inside: **Set variable** `tmp` with block `replace loop`, then **Set variable** `body` with block `copy back`.
    10. **Compose** `text`: block `text`.
    11. **Compose** `text_checks`: block `text checks`.
    12. **Select** `slot_checks`: From = output of `names_llm`, Map in text mode: block `slot checks`.
    13. **Filter array** `Filter_text_checks` on the output of `text_checks`, and **Filter array** `Filter_slot_checks` on the body of `slot_checks`. Condition for both: block `filter`.
    14. **Compose** `errors`: block `errors`.
    15. **Respond to the agent** (check the UI name) with three outputs: `instructions` (text) = output of `text`; `chars` (number) = block `chars`; `errors` (text) = block `errors text`.
    - Check: the flow saves without a red error. Write down every error text the designer shows, and which function it complained about (for example `replace`, `decodeUriComponent`, `item`, `union`). If a self-reference error appears on `Set variable`, write it down: that is why `tmp` exists.
19. Save and test the flow with its **Test** button (check the UI name), manually. Input `values_json`: the content of `flow-values-cio-insurance.json`.
    - Check: the run succeeds. Open the run history (check the UI name), open the action **Respond to the agent**, and copy the value of `instructions`. Write down the run time and the value of `chars`.
20. Save the copied value as `pilot/copilot-studio/spike/results/flow-cio-insurance.md`. Run the golden diff:
    - `diff pilot/copilot-studio/spike/results/flow-cio-insurance.md examples/cio-insurance/expected-instructions.md`
    - `node pilot/copilot-studio/spike/compare.mjs cio-insurance pilot/copilot-studio/spike/results/flow-cio-insurance.md`
    - Check: `diff` prints nothing and the helper prints `byte-identical: yes`. If the history shows the value with `\n` as visible characters, the helper unwraps JSON text itself; write that into the form. If the only difference is the final newline, or line endings, write that down exactly.
21. Repeat steps 19 and 20 with `flow-values-tprm-analyst.json`, the file `results/flow-tprm-analyst.md` and `examples/tprm-analyst/expected-instructions.md`. The cio-insurance case removes the `Tools` line and the `org_rule` line; the tprm-analyst case keeps the `Tools` line and removes only the `org_rule` line. Write the result into the form.
22. Injection case: run the flow with the content of `flow-values-injection.json` (golden profile of the TPRM analyst plus the slots from `evals/negative/injection-slots.json`).
    - Check: `errors` is not empty. The reference validator reports 4 errors for this file: (1) `tools`: line break, (2) `tools`: line starting with `#`, (3) `discretion_rule`: "ignore previous", (4) `discretion_rule`: send "automatically" without review. In the result form mark which of the four the flow reports (the `errors` output names the slot and the kind of problem). Error 4 is a regex rule in the reference; the flow can only approximate it. Write the full `errors` text into the form.
23. Answer in the form: which reference checks the flow can express exactly, which only approximately, which not at all. Reference checks: no `{{` left, length limit, 5 guardrail lines, 6 section headings, slot length limits, the 7 forbidden-content rules, placeholders declared in `placeholders_left`, description and starter limits. The checks in `flow-expressions.txt` cover the first five and most of the forbidden-content rules. Write what you had to leave out or could not build.

## Part 4. Call the flow as a tool from the agent (point 4)

24. In `Spike Agent` go to **Tools > Add a tool > Flow** (check the UI name) and add `Spike_RenderTest_email-triage_v1`. In its settings write a description: `Renders the email-triage template from a JSON text of slot values and returns instructions, chars and errors.` Save.
    - Check: the tool shows one input `values_json` and three outputs `instructions`, `chars`, `errors`. Write down the names and types the agent shows.
25. In the agent instructions write: `When the user sends a JSON text, call the tool Spike_RenderTest_email-triage_v1 with that exact text as values_json. Then show chars, errors and the instructions exactly as returned.` Save.
26. In the test chat paste the content of `flow-values-cio-insurance.json` as the message.
    - Check: the agent calls the flow and shows the result. Open the activity map or tracing view (check the UI name) and write down: was the tool called, was the input passed unchanged (count its characters; the file has the number printed in step 1), total run time of the flow, total time until the agent answered, any error text.
27. Copy the instructions the agent showed into `results/agent-cio-insurance.md` and run `node pilot/copilot-studio/spike/compare.mjs cio-insurance pilot/copilot-studio/spike/results/agent-cio-insurance.md`. Write down whether the agent returned the text unchanged. If the agent shortens or rewrites it, that is a finding: write it down.
28. Repeat step 26 with `flow-values-injection.json`. Write down what the agent said about the errors.

## Part 5. Copilot Studio extension for Visual Studio Code on your Mac (point 5)

If a step fails, write down the step number and the exact error text (take a screenshot), then skip to the result form. Do not look for a workaround in this checklist.

29. In Terminal run `uname -m` and `sw_vers -productVersion`. Write down both (expected: `arm64` and your macOS version). Open Visual Studio Code, run **Code > About Visual Studio Code**, write down the version.
30. Open the Extensions view, search for the Microsoft extension for Copilot Studio (check the UI name; the publisher is Microsoft), and click **Install**. Write down the extension name and version.
    - Check: the extension is listed as installed and enabled with no warning about the platform.
31. Open the Command Palette (Cmd+Shift+P), type `Copilot Studio` and write down the commands shown (check the UI name).
32. Sign in: run the extension's sign-in command or click its icon in the activity bar (check the UI name). Use the account of the test environment.
    - Check: the extension shows your account and lists the environments. Select the test environment.
33. Clone the empty agent `Spike Agent`: use the extension's clone or open-agent command (check the UI name), choose the environment and the agent, and choose an empty folder outside the repository (for example `~/spike-agent-clone`).
    - Check: the folder now holds YAML files for the agent. Write down the file names (names only, no content).
34. Edit the agent description in the YAML to `Spike test, do not use.`, then run the extension's **Push** (check the UI name; also called apply or upload changes).
    - Check: no error appears. Open the agent in the Copilot Studio web app: the description shows the new text.
35. In the web app change the description to `Spike test, second change.`, save, then run the extension's **Pull** (check the UI name; also called get changes).
    - Check: the local YAML file now shows `Spike test, second change.`.
36. Write into the form the result of each step (install, sign in, clone, push, pull) with the time it took and any error.

37. Delete `Spike Agent`, the flow and the prompt tool from the test environment when the lead confirms the result is read, or keep them for T-021 if the lead says so. Do not publish the agent. Do not share it with other users.
38. Send the lead the filled result form below and the folder `pilot/copilot-studio/spike/results/` (it contains only golden test data).
